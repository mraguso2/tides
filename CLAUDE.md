## Project

**Harbor Tides** — a nautical-themed PWA showing high and low tides at Eatons Neck, NY. Built for the local boating and fishing community around Northport, Centerport, and Huntington Harbor.

---

## Stack

- **Vite 8** — dev server and builds, config in `vite.config.ts`
- **TanStack Start** — full-stack React framework built on TanStack Router + TanStack Query + Vite
- **TanStack Router** — type-safe file-based routing, generates `routeTree.gen.ts` automatically via `tsr`
- **TanStack Query** — server state management with localStorage persistence
- **React 19** — UI
- **TypeScript** — strict mode
- **CSS Modules** — component styles (no Tailwind, no CSS-in-JS, no shadcn, no utility class libraries)
- **Biome** — linting and formatting
- **Vitest** — testing
- **vite-plugin-pwa** — PWA support and future local notifications
- **Cloudflare Workers** — deployment target via `@cloudflare/vite-plugin` and Wrangler

## Data — NOAA Tide API

**Endpoint (2026):**
`https://tidesandcurrents.noaa.gov/cgi-bin/predictiondownload.cgi?&stnid=8515786&threshold=&thresholdDirection=greaterThan&bdate=2026&timezone=LST/LDT&datum=MSL&clock=24hour&type=xml&annual=true`

Swap `bdate=2026` → `bdate=2027` for the second year fetch.

**Response:** XML with a full year of high/low tide predictions for Eatons Neck, NY (station 8515786).

**Each entry contains:** `date`, `day`, `time`, `pred_in_ft`, `pred_in_cm`, `highlow` (`H` or `L`)

**Fetching strategy:**
- On init, fetch the current year only
- If the user selects a date in a future year (the rolling 18-month window can span up to two year boundaries), lazily enable that year's query via TanStack Query's `enabled` flag
- All queries use a 4-week `staleTime` and localStorage persistence via `PersistQueryClientProvider` (`@tanstack/react-query-persist-client` + `@tanstack/query-sync-storage-persister`) wrapping the router in `router.Wrap`
- `gcTime` must stay `Infinity` — 4 weeks in ms overflows the 32-bit `setTimeout` limit (~24.8 days), which makes GC fire immediately and delete restored queries; the persister's `maxAge` handles stored-data expiry
- Tide data is client-only: no SSR loader prefetch (a loader fetch would hit NOAA on every server request). A warm cache must serve reloads with zero NOAA requests; only an empty or >4-week-old cache triggers a fetch
- NOAA fetches must be non-fatal: the UI falls back to localStorage-persisted data (or a notice) when NOAA is down
- Merge both datasets transparently — components never need to know which year they're reading from

**Service Worker registration must be client-side only** — TanStack Start is SSR-capable and browser APIs cannot run server-side.

## UI — Three sections, one page

1. **TideNow (hero)** — current tide state: rising or falling, height, and time until the next high or low. Most important section, seen first on mobile.
2. **TideStrip** — compact 3-day lookahead showing high/low times and heights.
3. **TideCalendar** — date picker showing a selected day's full tide schedule. Rolling cap: current month + 18 months. No months beyond that are browsable.

Future: `<AdCard />` component slots for local business ads. Keep structure clean enough to drop these in without refactoring.

## TypeScript rules

- Strict mode is on. No `any` — use `unknown` and narrow, or fix the type.
- No `// @ts-ignore` or `// @ts-expect-error` without a comment explaining why.
- Prefer `type` over `interface` unless extending is required.
- Use `satisfies` for config objects to catch typos while preserving inference.
- Export types from the same file as the implementation unless the type is shared across multiple files.

## Component conventions

- One component per file. Filename and component name match exactly.
- Every component gets its own folder with a `[ComponentName].tsx` and a `[ComponentName].module.css`.
- Named exports for all components except route-level page components (those use default exports as TanStack Start requires).
- Don't use `React.FC` — type props directly.
- Props type named `[ComponentName]Props`, defined immediately above the component.

```tsx
type TideNowProps = {
  entry: TideEntry;
  nextEntry: TideEntry;
};

export function TideNow({ entry, nextEntry }: TideNowProps) {
  return (
    <section className={styles.container}>
      ...
    </section>
  );
}
```

## CSS conventions

- CSS Modules only. No global classes outside `styles/`.
- All values from design tokens in `tokens.css` — never hardcode colors, spacing, or font sizes. Always use `var(--space-4)`, `var(--text-lg)`, `var(--brand-500)`, etc.
- Refer to `/design/tokens.md` for the color palette and font decisions before writing any styles.
- Component variants via `data-variant`, `data-state`, `data-size` attributes — not separate class names.
- Mobile-first — this app is primarily used on phones.
- Modern CSS only — no legacy hacks:
  - Centering: `display: grid; place-items: center`
  - Spacing: `gap` — not `margin + :not(:last-child)`
  - Viewport height: `100dvh` — not `100vh`
  - Full inset: `inset: 0` — not four separate properties
  - Aspect ratio: `aspect-ratio` — not padding-bottom hack
  - Parent-based styling: `:has()` — not JS class toggling
- Lean CSS: write only declarations that change the rendered output. Never restate browser defaults.
- No vendor prefixes — Vite handles them.
- `transition` lists only properties that actually animate — never `transition: all`.

## TanStack Router / Start

- Routes live in `src/routes/`. File name becomes the route path. The router auto-generates `routeTree.gen.ts` — never touch it.
- Every route file uses `createFileRoute` at the top — never write routes manually.
- Dynamic segments: `$paramName.tsx` → access with `Route.useParams()`
- Loaders handle data fetching at the route level. Prefer loaders over fetching in `useEffect`. Exception: tide data has no loader at all — it is client-only so NOAA is hit at most once per 4 weeks per device.
- Navigate with `<Link to="/path">` from `@tanstack/react-router` — not `<a href>`.
- Programmatic navigation: `const navigate = useNavigate()` → `navigate({ to: '/path' })`.
- Server functions use `createServerFn` — these run server-side only. Don't put browser APIs in them.
- Search params are typed via the route definition — use `Route.useSearch()`.

## TanStack Query

- All server state goes through Query. No `useState` + `useEffect` for data fetching.
- Query keys defined as constants in `src/lib/queryKeys.ts`:

```ts
export const tideKeys = {
  year: (year: number) => ['tides', year] as const,
};
```

- Mutations invalidate relevant queries in `onSuccess` or `onSettled`. Always be specific — never call `invalidateQueries` with no arguments.
- Tide data uses plain `useQuery` (no loader, no suspense) — NOAA outages must degrade to cached data, not crash SSR. Use `useSuspenseQuery` only for data that is guaranteed to resolve.
- localStorage persistence via `PersistQueryClientProvider` in `router.Wrap` with a 4-week `staleTime`/`maxAge` and `gcTime: Infinity` (see NOAA section for the setTimeout-overflow rationale).

- Server state → TanStack Query
